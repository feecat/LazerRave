# 兼容性与质量标准

本文定义样本范围和交付门槛。兼容状态区分源码实现、人工验证、自动样本通过和未实现，不以命令存在或单次启动成功推定完整支持。

## 当前基线

| 项目 | 状态 |
| --- | --- |
| Windows x64 `RelWithDebInfo` | 已完成本机构建和运行验证 |
| 1024×768、1920×1080 客户区 | 已完成窗口尺寸验证 |
| Base62、SCROLL、随机分支和长押 | 现有源码包含处理路径，待完整样本验证 |

| FMOD 音频与 EQ | 现有实现保留 |
| 多人房间、共享与实时排行 | 已接入；多真机同步、故障恢复及容量仍待完整验收 |
| BMSON、版本化新回放、云端重算与响度分析 | 尚未实现 |
| Windows ZIP 发布 | 已提供默认资源和依赖；干净设备及升级验收待完善 |
| 完整 DPI 与多语言 | 尚未完成验收 |

配置、皮肤和资源路径仍存在 CP932 兼容要求。内部 Unicode 支持不等同于界面已完成本地化。

## 样本管理

每个样本记录来源、许可、摘要、目标版本、预期语义和已知差异。测试素材需具备可再分发条件；个人曲库与第三方完整皮肤不得直接作为公开测试包。

皮肤样本保留截图及交互基线；谱面样本保留解析事件和规范化时间线；回放样本保留预期判定与统计。规范化及样本格式变更须显式版本化。

## LR2 皮肤

| 维度 | 验收范围 |
| --- | --- |
| 场景 | 选曲、决定、游玩、结果、段位或连续曲结果、键位设置及自定义 |
| 逻辑画布 | 640×480、1280×720、1920×1080，及已声明的自定义尺寸 |
| 指令 | 条件、选项、计时器、对象和数值映射、动画、相对资源路径 |
| 绘制 | 图集、字体、透明度、混合、裁剪、缩放及层次 |
| 资源 | DXA、图片、音频、视频、CP932 与 UTF-8 路径 |
| 交互 | 鼠标坐标逆变换、键盘导航、显示切换、重启和退出 |
| 多人侧栏 | 左右切换、隐藏、16 行与紧凑布局、旧皮肤视口和输入一致性 |

在 1920×1080 客户区内，4:3 皮肤可等比显示为 1440×1080，剩余 480 像素可用于侧栏。已有 16:9 皮肤需选择缩小视口、更宽窗口或覆盖布局。放大窗口不会增加原始图片细节。

OpenLR2 的皮肤实现持续以约定样本矩阵为验收范围，嵌入演奏与独立窗口分别记录结果。现有扩展接口见 [LR2 皮肤扩展](lr2-skins.md)。

## BMS 与 BMSON

| 维度 | 验收内容 |
| --- | --- |
| 文本与路径 | CP932、UTF-8、中日文路径、大小写、缺失资源及备用扩展名 |
| 索引 | Base36、Base62、音频与 BGA 定义、非法编号 |
| 条件 | RANDOM/IF 嵌套、固定种子与一致的分支展开 |
| 时间 | 小节长度、BPM、扩展 BPM、STOP、SCROLL、异常值 |
| 键型 | 约定的 5/7/9/10/14 键模式及单人、DP 语义 |
| 长押 | LNOBJ、LNTYPE 与约定扩展；按规则版本区分成绩 |
| BMSON | 以 1.0.0 为目标，验证音频切片、重叠、时间和资源语义 |
| 音频与 BGA | WAV、OGG、MP3 等按解码器验证；视频单独建表 |
| 错误处理 | 损坏文件、异常长度、过多事件、条件异常及资源越界 |

传统 BMS 系列覆盖 BMS/BME/BML/PMS。BMSON 0.21 等历史版本属于可选扩展，须另行定义兼容策略。支持范围应以规范版本和命令集合表述。

原始谱面、资源包和展开时间线分别标识。MD5 用于旧数据关联，SHA-256 用于新内容完整性。相关接口见 [BMS 扩展](bms.md)；BMSON 实现依据 [规范文档](https://bmson-spec.readthedocs.io/en/master/doc/index.html)。

## DPI 与多语言

测试分别记录界面逻辑尺寸、物理客户区和皮肤逻辑坐标。矩阵包含 100%、125%、150%、175%、200% 缩放，多显示器切换，1024×768、1920×1080 及高 DPI 屏幕，以及窗口和全屏切换。

客户端使用上游本地化资源与新增文本表。验收 zh-CN、en-US、ja-JP 的文本扩张、字体回退、IME、长昵称和签名、路径编码、数字及时间格式。缺失翻译使用默认语言回退并产生诊断。

旧皮肤图像中的文字按皮肤资源管理，不能由消息本地化系统自动翻译。兼容层保留既有编号与计时器。

## 回放与确定性

- 相同时间线、规则版本、随机种子和输入事件流重复执行，判定及统计逐项一致。
- 覆盖预按键、负时间、同刻按下与松开、长押、转盘、随机、暂停、退出、速度和偏移设置。
- 字段宽度、单位、字节序及偏移应用位置固定；版本不支持时明确拒绝或采用已定义兼容规则。
- 保留旧 `.lr2rep` 样本；无法恢复的元数据明确标记。
- 损坏、截断、事件超限、队列溢出和身份错误不得标为可验证。
- M6 使用匹配版本的 OpenLR2 后端重算结果并与客户端统计比较，失败原因可追踪。

回放设计与分阶段验证状态见 [多人协议与回放](../architecture/multiplayer-and-replay.md)。

## 响度与音频扩展

响度参考采用选定谱面及随机分支的自动演奏混音，包含 BGM 和 keysound。整曲应用统一增益以保留素材比例，不逐个 keysound 归一化。实际游玩中漏键可能改变混音，不能保证每次游玩获得相同综合响度。

分析缓存包含资源、时间线及算法版本。处理可关闭，设置增益上限与峰值余量。响度补偿、EQ、动态压缩和限幅分别配置。测量方法参考 [EBU R128](https://tech.ebu.ch/publications/r128)，目标响度经试听、峰值及延迟验证后确定，不直接采用广播目标值。

带前视的限幅需报告附加延迟并纳入校准。音频扩展接入现有 OpenLR2/FMOD 路径，须分别验证调度、混音、重采样及解码缓存的影响。

## 实时性能

在同机、同设备、同采样率及缓冲大小下建立基线，再比较新实现：帧时间 P50/P95/P99、输入到音频时间、抖动、音频欠载、DSP 延迟与 CPU 占用。

功能扩展的初始门槛为新增延迟 P95 不超过基线 2 ms，连续 30 分钟无新增音频欠载。测量方法、仪器和最终预算在对应功能接入前固定；未达标的扩展不默认启用。
