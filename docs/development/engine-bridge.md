# 启动器与游戏桥接

当前桥接连接 C# / osu!lazer 桌面客户端与 C++ OpenLR2，实现具体谱面直达、单次演奏参数、共享曲库及 Windows 原生子窗口内演奏。现有皮肤、演奏、结果、成绩及回放流程继续由 OpenLR2 执行。命名管道和实时状态通信属于后续工作。

## 构建与运行

```powershell
./build.cmd
```

桌面构建自动更新并打包 C++ 引擎。单独调试 C++ 时，可执行 `./build.cmd -EngineOnly -UpdateRuntime` 更新已经准备过的 `out/reports/engine-runtime/x64/RelWithDebInfo/`，仅替换 EXE、FMOD DLL 与 PDB；配置、资源、曲库、成绩和回放保持原状。游戏正在运行时拒绝更新。首次准备该调试副本仍使用 `-PrepareRuntime`，两个选项互斥。

桌面普通构建将引擎与运行资源复制到同一产物文件夹，客户端固定读取 EXE 所在目录的曲库，不提供运行目录选择。添加其他曲库目录后执行扫描，将曲目写入共享数据库。曲库页的开始按钮使用当前难度对应的绝对谱面路径。直接启动随包附带的 OpenLR2 可使用经典菜单流程。打包规则见 [桌面前端](client.md)。

## 单次演奏

客户端先无窗口校验请求，再启动可见演奏进程。引擎复用 `cmd_directplay` 路径，从演奏场景开始；结果页、重试与退出继续使用原有行为，离开演奏会话后进程退出，客户端重新读取曲库。

| 字段 | 范围与含义 |
| --- | --- |
| chart | 存在的绝对 `.bms`、`.bme`、`.bml` 或 `.pms` 路径，确定具体难度 |
| speed | 50–1000，客户端倍率乘以 100；2.75 对应 275 |
| offset | −1000 至 1000 ms，直接映射 LR2 judgetiming |
| arrangement | 0 关闭、1 镜像、2 随机、3 S-RANDOM、4 SCATTER、5 CONVERGE，映射现有随机排列枚举 |
| play-options | 63 个具名演奏选项；每个 option 带 name 与整数 value，范围按引擎原有单位校验 |
| encoding | auto、utf-8、cp932 或 gb18030，指定谱面文本解码方式 |
| render-profile | baseline、uncapped、vsync、directshow、discard、no-bga、rgb-video，仅嵌入模式使用 |
| frame-limit | 0 跟随显示器、−1 不限帧或 30–1000；uncapped 与 vsync 预设使用各自策略 |

演奏选项覆盖判定槽、1P/2P 轨道排列、BATTLE 系列、速度固定、基础速度、HIDDEN/SUDDEN、遮挡、LIFT、辅助、BGA、目标分数、回放保存及 MANIAC 扩展。`play-options` 覆盖原生配置中的对应字段；未携带该节点的旧请求保留既有直达行为。速度倍率控制音符滚动，不改变音频速度。Autoplay 使用原有自动演奏入口并禁用成绩写入。no-bga 渲染预设优先于 BGA 选项。

前端字段定义位于 `engine-bridge/PlayOptions.cs`，引擎范围及字段映射位于 `LR2_launcher_options.inc`。新增该能力使用 `LAZERRAVE_PLAY_OPTIONS_V1` 标识，旧引擎会被客户端拒绝。`validate` 响应包含应用后的演奏选项，供无窗口检查读取。

会话退出时不写回经典配置；独立窗口路径的窗口尺寸由随包附带的窗口设置脚本处理。

直达演奏不附加 `-ns`，已入库谱面的成绩与回放沿用引擎规则。直接运行 OpenLR2 的经典入口沿用其自身配置与保存规则。账号、皮肤、输入与音频设备仍读取运行目录配置，启动器中的音频、键位及皮肤偏好尚未传入游戏。

## Windows 原生嵌入

Windows 嵌入演奏的可选字段为 `embed-window` 和 `host-process`，分别为前端子窗口句柄的十进制无符号整数和窗口所属进程 ID，必须同时出现，仅用于 `play`、`validate` 及诊断用 `embed-probe`。引擎在图形初始化前拒绝无效、已销毁、非子窗口或进程身份不符的目标；前端同时检查 `LAZERRAVE_EMBED_V1` 能力标识。

嵌入初始化成功后，`.reply.xml` 包含 `engine-window` 和 `viewport` 确认信息。前端核对游戏窗口所属进程及承载句柄，再转交窗口消息。停止请求通过原请求路径追加 `.stop` 的文件通知，并可对确认后的游戏窗口发送 `WM_CLOSE`。嵌入模式不调用窗口配置脚本，不写回经典配置；演奏画面由原生承载区域显示。完整行为与验收见 [桌面前端](client.md)。

`embed-probe` 是内部诊断入口，仅接受有效嵌入目标。它创建隐藏游戏窗口、初始化 Direct3D 并输出短暂测试帧，不读取个人配置、曲库、成绩或回放，不启用音频；它属于图形诊断，不属于无图形后台模式。

## 共享曲库

共享数据库为运行目录中的 `LR2files/Database/song.db`。客户端通过引擎导出读取曲目，不自行维护第二个数据库，不以另一套扫描器覆盖引擎元数据。

- 启动时同步设置中的曲库目录，游戏退出时只读导出；运行目录始终为桌面 EXE 所在文件夹。
- 设置中的曲库目录是客户端与经典模式的共同来源，不附加经典 `config.xml` 中的旧目录。扫描更新目录、哈希、元数据和已删除曲目，沿用标签覆盖。
- 为捕获同一秒内新增的文件，每次同步枚举目录；未变谱面复用哈希快照，修改文件重新解析。
- 同步使用 SQLite 写事务，初次同步前创建数据库备份；取消后台操作时终止该后台子进程，未提交事务由 SQLite 回滚。
- 设置中的目录写入独立 UTF-8 `lazerrave-roots.xml`，经典模式在内存中替换曲库来源，保存时恢复原配置的完整目录列表。没有该文件的独立 OpenLR2 运行包仍读取原配置。移除全部目录会得到空曲库，不回退读取旧目录；同步只清理曲库索引，不删除歌曲、成绩或回放文件。
- 客户端仅展示有效根目录内仍存在的谱面，按实际文件夹构建层级，并使用引擎提供的键型、等级、难度、BPM 和音符数。
- 同步核对谱面内容哈希，捕获同一秒内的修改及保留旧时间戳的文件替换。
- 最佳成绩以当前经典玩家档案为准，通过原有成绩校验后导出 EX SCORE。没有有效记录时显示空值，读取失败时保留曲库并报告警告；不创建或修改成绩数据库。

同步更新曲库，不修改谱面、素材、成绩或回放文件。不支持实时数据库通知、跨客户端收藏同步、历史游玩记录、真实回放入口、BMSON 或段位连续演奏。原有扫描器对符号链接、极长路径和异常文件的处理仍需后续完善。

## 文本编码与元数据修复

谱面头部与完整谱面解析使用相同的解码规则：UTF-8 BOM 优先；自动模式识别有效 UTF-8，否则按 CP932 读取。GBK 与 CP932 的字节范围存在重叠，不进行自动推断；中文旧谱面可在设置中明确选择 GB18030 / GBK。该设置作用于当前运行目录的曲库，混合编码曲包使用自动模式，并在后续扩展为按目录指定编码。显式选择 UTF-8 要求输入为有效 UTF-8。

编码变更后自动重建元数据。也可在设置中手动执行“重建谱面元数据”，重新读取未改变哈希的谱面，修复数据库中已缓存的乱码标题。首次重建前创建 `song.db.before-metadata-repair.bak`。重建以写事务执行，仅更新元数据字段，保留哈希、收藏、入库时间以及独立的成绩和回放文件。标签数据库中的人工覆盖继续生效。经典配置 XML 仍沿用原有编码。

同一哈希对应多个路径时，直达演奏优先匹配选定路径的数据库记录，再从该文件读取文字和资源路径；成绩仍按哈希关联。皮肤 CSV 同样识别 UTF-8 / CP932，旧图片字体的 CP932 字符映射保留。编码修复不会为图片字体增加缺失字形；方框、空白字与错误汉字需分别验收。

## 协议

调用格式：`OpenLR2_x64.exe --lazerrave-request <绝对请求路径>`。请求根元素为 `lazerrave`，属性 `version="1"`，`mode` 支持 `catalog`、`sync`、`refresh`、`validate`、`play`。客户端请求存放于运行目录的 `cache/engine-requests/<唯一标识>/`，每个请求使用独立临时目录，字段采用 UTF-8 XML 元素。

客户端的曲库请求使用 `<library-source>settings</library-source>` 明确目录来源，包含零个或多个 root 元素；只读导出同样按请求目录过滤，零个 root 表示空曲库。进入经典模式前同步设置目录，保证入口一致。

`catalog`、`sync`、`refresh` 和 `validate` 在图形与音频初始化前执行，不创建游戏窗口。`refresh` 在同步后强制重读全部谱面元数据。响应写入请求路径追加 `.reply.xml` 的文件，包含版本和 `status="ok"` 或 `status="error"`；错误时附带 message 并返回退出码 2，成功返回 0。曲库导出包含 root 元素与 chart 属性记录，score 属性表示通过校验的最佳 EX SCORE，warning 元素记录成绩读取等非致命错误。`play` 进入原有游戏循环，以进程结束状态反馈会话结果。

客户端预先检查引擎二进制是否包含桥接版本标识，拒绝向旧版引擎发送新请求，防止旧程序将未知参数忽略后打开窗口。经典入口仍可用于旧版引擎。后台请求可取消，最长等待 600 秒；超时或失败不会自动进入经典模式。

## 验证

`./build.cmd -CompileOnly` 只编译前端和引擎，不启动程序或执行测试。协议回归用例保留于 `scripts/tests/test_engine_bridge.py`，仅在显式配置独立测试环境后运行，操作入口见 [自动检查](verification.md)。

可见演奏、皮肤绘制、输入、音频、结果保存及重试须使用真实运行资源人工验收。构建成功不代表这些流程已验证。
