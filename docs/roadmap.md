# 开发路线图

LazerRave 沿用 C# / osu!lazer 客户端与 C++ OpenLR2 演奏架构，以同窗口嵌入为默认方式，保留独立窗口和经典 LR2。当前已有 Windows Beta 发布包、在线 IR、曲包下载与多人房间，后续重点为可靠性、可信成绩和兼容扩展。

## 阶段与交付目标

| 阶段 | 已有基础 | 待交付内容 |
| --- | --- | --- |
| M0：构建基线 | 单一构建入口、输出隔离、版本与 ZIP 打包 | 干净开发环境复现、公开兼容样本 |
| M1：桌面客户端 | 层级曲库、筛选、设置、窗口恢复与引擎嵌入 | 完整 DPI、本地化与预览音频验收；BMS 编辑入口 |
| M2：账号与内容 | 账户、自动登录、公开曲包、客户端浏览下载、IR 与难度表 | 账户恢复、元数据审核完善、存储与出口扩展 |
| M3：桥接与回放 | XML 启动与状态快照、本地成绩、LR2 回放及完整性检查 | 加载屏障、能力协商、版本化输入记录、云端回放 |
| M4：多人游戏 | 16 人房间、准备、倒计时、实时排行、结果、房主转移、踢人及强制开始 | 多机同步和故障恢复；可选自动分享 |
| M5：Beta 质量 | 渲染预设、日志与性能诊断工具 | 长时间稳定性、容量测试、恢复演练、可关闭的响度与音频扩展 |
| M6：兼容与验证 | BMS 与旧皮肤实现、经典课程基础 | BMSON、可重复回放重算、独立课程认证与课程 IR |
| M7：发行完善 | 带依赖和默认资源的 Windows ZIP | 干净设备验收、升级与回滚验证、默认资源及依赖持续审计 |
| S：Steam，可选 | 自有用户身份 | 外部身份绑定、票据验证与发行渠道接入 |

阶段编号用于关联接口和验收范围，不表示严格串行工期。当前实现状态详见 [客户端](development/client.md)、[云端服务](development/cloud.md) 与 [IR](architecture/internet-ranking.md)。

## 实施顺序

1. 完善现有本地游玩、设置、扫描、窗口和完整曲目预览的验证；保持离线游玩不依赖登录。
2. 建立可重复的双机多人验证，覆盖准备、加载、倒计时、完整演奏、断线和结果。
3. 补齐内容生命周期、账户恢复、备份与容量测量，再扩展并发规模。
4. 在匹配版本的 OpenLR2 上验证确定性重播，随后接入云端回放与可信成绩。
5. 基于版本化课程模型接入连续演奏、血槽继承、本地记录和课程排行。
6. 在既有皮肤及回放兼容基础上扩展 BMSON、BMS 编辑和音频处理。

新闻、更新日志和在线搜谱继续复用保留组件，按自有服务的数据来源逐步接入，不恢复 osu! 专属业务。编辑器先实现 BMS 模型与安全保存，再开放入口。Steam 独立于本地功能和核心账户体系。

## 固定约束

- 判定、输入和音频在本地执行，不等待网络、压缩或数据库任务。
- 缺曲检查以谱面文件身份为准；共享 ZIP 仍执行内容完整性校验。
- 房主分享采用普通 ZIP 的最高 Deflate 压缩等级；下载必须由成员确认并显示进度。
- 共享及网站曲包安装到 `BMS/Shared/`，保持歌曲多难度分组；临时服务器副本校验完成后固定保留 2 小时。
- 实时成绩与未重算的 IR 成绩不标为服务器验证结果；EX SCORE 与清灯记录分别维护。
- 用户曲库、配置、成绩及回放不进入默认发布包，也不随更新覆盖。

## 验收要求

| 范围 | 门槛 |
| --- | --- |
| 本地 Beta | 完整演奏、返回、设置持久化、窗口切换和默认资源可用 |
| 多人完善 | 双真机整局、16 协议会话及多机验证，过期消息与断线恢复正确 |
| 在线扩容 | 实测 CPU、内存、磁盘与出口；备份恢复和回滚演练 |
| 可信成绩 | 同时间线、规则、种子和输入重播得到相同判定与统计；不支持版本明确拒绝 |
| 编辑与兼容 | BMS 保存往返校验、BMSON 样本及旧皮肤矩阵通过 |
| 发行完善 | 干净设备无需既有 LR2 安装，完整包可启动，升级保留个人数据 |

详细约束见 [质量标准](compatibility/quality.md)、[多人协议与回放](architecture/multiplayer-and-replay.md)、[课程认证](architecture/course-certification.md) 和 [服务器容量](operations/server-capacity.md)。
