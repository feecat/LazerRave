# 技术栈与模块边界

LazerRave 采用 C# 桌面客户端、C++ OpenLR2 演奏进程及独立云端服务。界面复用裁剪后的 osu!lazer，BMS 判定与 LR2 皮肤由 OpenLR2 执行；同窗口为默认集成方式，保留独立窗口和经典入口。

## 当前技术栈

| 层次 | 技术与职责 |
| --- | --- |
| 桌面界面 | C# / .NET 10、osu!lazer `OsuGame`；菜单、选曲、设置、在线界面 |
| 演奏引擎 | C++23、DxLib、FMOD；输入、音频、判定、BMS 与旧皮肤 |
| 游戏桥接 | UTF-8 XML 请求、响应与后台写入的成绩快照；Windows 原生子窗口 |
| 本地存储 | OpenLR2 SQLite 曲库与成绩、客户端持久存储、TOML 设置及演奏 XML 记录 |
| 云端网站 | React、TypeScript、Vite；账户、IR、难度表、曲包与管理后台 |
| API 与房间 | ASP.NET Core 10、SignalR；认证、房间状态、内容授权及成绩接收 |
| 关系数据 | PostgreSQL、Npgsql、版本化 SQL 迁移 |
| 内容存储 | 首版本地内容卷；ZIP、SHA-256、分块上传和受控下载 |
| 部署 | Ubuntu x86-64、Docker Compose、Caddy HTTPS |

.NET SDK 固定为 10.0.401，vcpkg 基线由原生工程清单固定。上游来源见 `src/osu-lazer/LAZERRAVE-UPSTREAM.md`，源码与输出职责见 [仓库结构](../development/project-layout.md)。

## 进程与通信

客户端协调曲库、设置、账户、房间、下载和游戏生命周期；OpenLR2 独立处理加载、音频、输入、判定和绘制。两端通过会话文件传递请求及成绩，原子替换避免读取半写入快照。客户端将实时统计上传至房间服务，服务广播排行并收集结果。当前已接入倒计时启动、实时排行与结果页，不具备完整的加载屏障和精确时间线同步。

客户端与网站通过 HTTPS/WSS 使用自有服务。公开曲包和临时房间分享采用不同授权及生命周期；服务端数据库存元数据、摘要与权限，文件置于内容卷。初期房间状态由单实例管理，多实例路由和独立后台任务节点属于后续扩展。

音频、输入和判定不等待网络、数据库、压缩或下载。扫描、打包与校验采用受控后台任务。前端和引擎具有独立绘制循环；嵌入视口需分别验证焦点、DPI、输入坐标及 GPU 生命周期，前端 FPS 不等于原生演奏帧率。

## 身份与成绩

账号采用自有用户标识，网页使用 HttpOnly Cookie，桌面使用可撤销 Bearer 会话。密码由 Identity PBKDF2 处理，桌面会话使用 Windows DPAPI 按当前用户加密后持久化；本地游玩不依赖登录。

成绩以谱面内容身份关联，保留 EX SCORE、普通 SCORE、判定和游玩选项。实时快照和客户端提交成绩不等同于服务器重算结果。现有 LR2 回放在本地记录和重播，云端回放上传及重算尚未接入。

## 扩展边界

- 命名管道及能力握手：替代或扩展现有会话文件，建立加载确认和可取消控制。
- 回放验证：使用匹配版本的 OpenLR2 重算，先验证确定性，不假定 Windows 引擎可直接在 Linux 服务运行。
- 课程与编辑：基于现有课程和编辑器基础接入版本化 BMS 模型及安全保存。
- 存储与容量：实测后再引入对象存储、多实例路由或任务节点。
