# 段位与课程认证

## 现有基础

经典 OpenLR2 已具备 COURSE、NONSTOP 与 CLASS 三类课程。主菜单中的原生 LR2 入口可进入这些菜单，使用原生课程编辑、演奏及结果流程。当前客户端直达桥接仍按单谱面启动，尚不提供独立的课程认证页面或课程成绩上传。

原生课程定义保存在 `LR2files/Database/song.db` 的 `expert`、`nonstop` 和 `grade` 表。`LR2_songmanage.cpp` 中的 `WriteCourse` 与 `SearchCourseFromDB` 是定义写入和读取边界；不应直接将课程目录当作普通歌曲目录导入。

原生 `hash` 包含 32 字符的课程选项头，后接按演奏顺序排列的谱面 MD5，每个 MD5 占 32 字符。选项头包含轨道连接及课程类型，并有密码摘要相关字段。现有引擎最多使用 10 个阶段。课程身份必须包含完整的选项头与有序谱面列表；仅按课程标题或无序谱面集合计算身份不足以区分课程。

云端迁移 3 已提供 `courses`、`course_stages` 与 `course_scores`，但尚无管理、演奏和成绩提交接口。云端阶段表允许 20 阶段；首版 OpenLR2 适配器须限制为 1–10 阶段，不能静默截断。

## 集成顺序

1. 只读课程目录：读取三类原生课程，展示键型、阶段、缺失谱面及可演奏状态。以 MD5 匹配本地谱面，以 SHA-256 固定实际展开的版本。
2. 版本化课程定义：保存课程类型、顺序、键型、轨道连接、血槽规则和选项限制。课程变更生成新版本，不覆盖历史认证身份。
3. 原生课程桥接：复用 OpenLR2 的课程准备、阶段转换与课程结果流程，增加显式能力握手及完整错误回复。不能用多次单谱面启动模拟认证。
4. 本地课程记录：包含课程版本、各阶段身份与判定、聚合 EX SCORE、最大分数、血槽状态、完成或中断状态及分阶段回放。
5. 云端目录与排名：先提供已提交记录，再接入匹配引擎版本的回放验证。未验证成绩不能标为已认证。

## 演奏与成绩规则

OpenLR2 在课程阶段之间继承血槽和课程状态。`Main.cpp` 的课程阶段转换及 `LR2_statplay.cpp` 的课程清灯判断必须保留；普通单曲 NORMAL/EASY 的 80% 清灯条件不能直接用于课程。当前原生实现的课程存活条件为至少 2%，具体失效、选项限制及清灯含义仍以所选课程模式为准。

课程认证应分别展示是否通过、血槽类型、完成阶段、EX SCORE 和分数评级。评级不等于通关状态。认证榜须明确固定课程及血槽规则；不能沿用普通谱面榜的跨血槽汇总来授予段位。

## 验收门槛

- 阶段缺失、身份改变或不支持的选项在开始前明确拒绝。
- 同一进程连续演奏，阶段间血槽连续，结果与经典模式一致。
- 中断和自动演奏不授予认证；强制关闭后可恢复界面且不生成通过记录。
- 每阶段回放可关联原始谱面、规则及种子，损坏回放明确标记。
- 课程版本更新后，旧记录仍关联原定义。

课程桥接与认证接口尚未实现，现有经典入口保持可用。
