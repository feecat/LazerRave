# 多人协议与回放设计

本文定义完整多人游戏与回放的目标协议约束。首版云端已实现 16 人房间、准备、倒计时、统计与聊天，并接入桌面临时曲包分享、显式下载和 Shared 安装，具体运行协议见 [云端网站与服务](../development/cloud.md)；桌面倒计时启动、原生 XML 成绩流、实时排行与结果页已接入；统一游戏加载屏障、精确时间线同步、命名管道控制与回放重算仍未完成。首期目标为最多 16 人的同谱面对局，采用 HTTPS 内容传输与 WSS 房间通信；游戏输入、音频和判定在本地执行。

## 对局模型

同一对局固定谱面、键型、规则版本和随机分支。实时排行默认按 EXSCORE 展示，同分顺序在规则中固定；网络包到达先后不参与判定。客户端快照在服务器重算前属于临时结果。

16 人是网络房间容量，不通过扩大当前本地玩家数量常量实现。中途加入者等待下一局，房主转移不改变进行中对局的服务器所有权。

## 版本与消息字段

| 字段 | 含义 |
| --- | --- |
| 协议主版本、次版本 | 不兼容变更与向后兼容扩展 |
| 能力集合 | 客户端及游戏后端支持的功能 |
| 请求标识 | 请求与响应关联、幂等处理 |
| 序号 | 同连接或同消息流的顺序检查 |
| 房间版本号 | 检测过期状态与并发修改 |
| 用户、设备、房间、对局标识 | 明确消息所属实体 |
| 消息类型与载荷 | 控制命令、确认、错误或状态快照 |

用户身份由服务端会话绑定，不信任载荷中自报的身份。未知主版本拒绝连接；次版本和能力协商按明确规则降级。初版采用可诊断的文本消息，具体编码、字段宽度、大小上限和错误码在 M3 冻结，不使用原生结构体内存布局作为协议。

## 内容与规则身份

| 身份 | 用途 |
| --- | --- |
| 原始谱面 SHA-256 | 区分谱面文件内容 |
| 规范化资源清单摘要 | 上传、下载 ZIP 的完整性检查；不用于判定本地是否拥有谱面 |
| ZIP 文件摘要 | 传输完整性；不代替内容身份 |
| 展开时间线摘要及算法版本 | 标识随机分支和解析结果 |
| 解析器、规则及引擎版本 | 定义可重播与可验证范围 |
| 随机种子及游玩修饰 | 固定分支、排列及影响成绩的选项 |

MD5 仅用于旧 LR2 数据关联。路径规范化、排序、大小写及编码规则须版本化，防止不同平台产生不同清单。通过 OpenLR2 后端接口获得并核验一致的展开结果，前端不另行复制游戏解析与判定逻辑。

## 房间状态

| 状态 | 进入条件与职责 |
| --- | --- |
| Lobby | 选曲、配置规则和成员管理 |
| ContentPending | 缺谱成员确认下载，安装时检查传输完整性 |
| Loading | 游戏进程加载固定内容与规则 |
| Ready | 所需成员完成加载与身份确认 |
| Countdown | 服务器公布计划开局时间并等待确认 |
| Playing | 本地游玩，上传进度和统计快照 |
| Finishing | 收集结束状态、成绩和回放 |
| Results | 展示临时结果及后续验证状态 |

结果结束后返回 Lobby。成员状态分别记录下载中、加载中、已准备、游玩中、已完成、断开和失败。选曲、规则或参赛成员变化使既有准备状态失效。

服务器为每个状态规定超时、可接受消息和失败结果。重复消息不得重复开局；过期对局消息不得修改新对局；房主离开、游戏崩溃或服务重启均须产生可恢复的明确状态。

## 开局与时间

服务器维护计划开局时刻。客户端通过多次往返测量估计服务器时间与本地单调时钟的偏移，并记录测量误差。初始倒计时预算为 3 秒，按加载和网络测试调整。

客户端在计划时刻启动本地时间线。确认缺失、时钟误差超限或加载迟到时，按协议取消或重新准备，不将网络延迟直接加到判定窗口。音频时钟与输入时钟的校准由后端独立完成。

## 实时成绩与侧栏

当前统计快照广播约为 10 Hz，桌面发送端合并旧状态，原生引擎以工作线程写入约 120 毫秒一次的会话 XML。客户端上传进度、判定统计、EXSCORE、连击及运行状态；服务器广播房间最新快照。头像和名称随成员资料传输，不随每帧重复发送。

容量预算为每人每次上行 512 B、每名接收者每次房间下行 4 KiB，实际编码后必须测量。连接积压时允许合并旧快照并保留最新值，控制命令使用有界可靠队列；持续超限连接按策略断开。

当前嵌入模式在游戏视口右侧显示排行，独立窗口模式在前端窗口显示；左侧和隐藏选项属于后续扩展。布局适配皮肤视口，输入坐标使用逆变换。服务端断开时保留本地游玩，排行显示连接状态与数据时效。

## 游戏进程桥接

当前桥接以独立会话目录的 XML 请求、响应和成绩流连接前端与原生引擎；成绩写入采用后台线程与原子替换，退出前刷新最终快照。后续 Windows 命名管道采用当前用户 ACL、随机管道名和会话令牌。消息以长度前缀封装，建立版本与能力握手、最大帧长度、超时和请求关联。

控制接口覆盖加载内容、准备、计划开局、取消、结束和退出。状态接口覆盖进程、场景、加载、游玩统计、结束原因及回放完整性。

IPC 线程只负责通信与校验，主线程消费控制队列。音频和输入线程不等待 IPC。状态副本与事件队列采用有界容量，回放事件溢出时标记记录不完整，不能静默丢失后继续标为可验证。

## 曲目上传与分发

本节定义曲目分发协议与目标体验。房主本地选曲、资源清单、分块上传及续传、成员授权下载、进度、Shared 安装和服务端固定 2 小时清理已实现；房主自动分享选项、本地缓存自动回收和游戏后端加载确认仍待接入。

### 用户流程

1. 房主在现有层级曲库中选择歌曲和难度。客户端公布原始 BMS 文件的 SHA-256，各成员仅匹配 BMS 内容，不要求文件名、文件夹层级、绝对路径或资源清单一致。资源清单仅在房主确认上传后生成。
2. 全员已有所选 BMS 时可直接准备，不打包、不上传；音频、图片或 BGA 缺失不会标记为缺曲，也不阻止选择与准备。
3. 有成员缺曲时，房主点击一次“上传并分发”。已启用多人房间自动分享的房主可自动执行；取消、上传失败和超额时保留明确操作入口。重复选曲优先复用尚未到期且有权访问的内容，无需重新上传。
4. 房主客户端后台打包完整单曲目录为普通 ZIP，选择以最小体积为目标的压缩设置；打包和上传可取消，显示进度。C# 路径采用 `CompressionLevel.SmallestSize`，不把枚举值作为数值压缩等级；接口定义见 [.NET CompressionLevel](https://learn.microsoft.com/en-us/dotnet/api/system.io.compression.compressionlevel)。服务器接收与校验，不重新压缩。
5. 服务器校验完成后广播内容可用事件。缺曲成员点击“下载曲目”后开始下载，界面显示百分比、已下载与总大小、速度及预计剩余时间，并提供取消和失败重试。完成后自动校验、解包并原子安装到程序根目录下的 `Shared`，增量更新共享曲库，按所选谱面摘要定位难度。已拥有完整内容的成员跳过下载。
6. 安装及游戏后端加载确认成功后，客户端自动报告内容就绪；玩家的“准备”操作仍控制是否参赛。正常开始要求全员准备并匹配 BMS。房主可强制开始，跳过准备状态，仅将匹配 BMS 的玩家加入固定参赛名单；其他玩家留在房间。服务器使用三秒倒计时，并仅接收本局参赛者的统计。等待和结算阶段支持房主踢人和转让房主。

房间界面显示缺曲、待下载、压缩、上传、下载、校验、加载、就绪及失败状态。正常分发由房主确认上传，每位缺曲成员点击一次“下载曲目”；准备与开始属于独立的游玩操作。下载不能由选曲或入房直接触发，也不提供省略确认的自动下载选项。新的缺曲选曲需要新的下载确认，已完整缓存的内容可直接复用。玩家不需要手动选择 ZIP、解压目录或重新扫描整个曲库。

下载进度与校验、解包、加载状态分别显示，传输完成不等于内容就绪。取消后保留可恢复暂存，只有玩家点击继续或重试才恢复。房主换曲时取消旧曲下载并提示新的待下载内容，不自动下载新曲。

打包范围以完整单曲资源目录为初期基准，保留该歌曲的多个难度、音频、图片和 BGA，不打包上级曲包、账户数据或程序文件。打包只枚举单曲目录内实际存在的资源，缺失引用不阻止分享；不自动读取目录外文件，额外资源需要用户自行整理。现有客户端按路径生成的本地 ID 继续用于界面映射；联网另建真实文件内容摘要和资源索引，不把路径 ID 当成谱面摘要。

### 上传与授权

房主可以选择未进入公开目录的本地谱面。选曲首先建立待确认的内容身份，不要求拥有管理员权限或先发布公开曲包。临时上传授权绑定房主、房间、选曲版本与内容身份；上传过程中换曲会取消绑定，旧上传不得覆盖新选曲。

采用规划中的 8 MiB 分块可恢复 HTTPS 上传，限制并发，流式写入磁盘，禁止把完整 ZIP 缓存在服务器内存。上传完成前预留配额，失败及未完成会话按期限回收。客户端下载支持 Range 恢复，最终核验 ZIP 摘要、资源清单及谱面内容。

临时内容只授权当前房间成员访问，不自动进入公开曲包目录。每次申请下载或续传均检查用户、房间成员资格、内容绑定和有效期。同一内容的复用不能向无权访问的用户泄露上传记录，也不能延长既有到期时间。

### 两小时生命周期

临时 ZIP 从上传完成并通过校验的服务器 UTC 时间起保留 **2 小时**。到期时间写入 PostgreSQL，选曲、下载、重复引用、房主转移或服务重启均不刷新保留期。管理员发布的预设曲包使用独立生命周期，不受此规则影响。

到期后立即停止新下载及续传授权，中止未完成传输，并在下一次清理任务中删除服务端 ZIP、分块和临时资源清单。清理周期目标为一分钟；服务启动时补清理过期内容，失败重试并记录原因。物理删除后回收占用配额，保留必要的到期与对局元数据，不删除已用于成绩关联的谱面身份。

正在演奏的成员使用已安装的本地文件，服务器到期删除不影响演奏。正在获取内容的成员显示“分享已过期”，由房主重新上传产生新的有效期；不能暗中续期。房间显示剩余保留时间，预计无法在到期前完成分发时提示重新上传。

客户端固定安装目录为 `<程序根目录>\Shared\`，相对于 `LazerRave.exe` 所在目录定位，不依赖启动时的工作目录。每首歌曲按资源清单摘要安装到独立子目录，保留原始相对资源路径及多个难度；不同版本并存，完整相同版本复用，不覆盖已有曲目。

下载及解包暂存位于 `Shared\.incoming\<传输标识>\`，曲库扫描排除该目录。校验成功后原子移动到正式歌曲目录，再更新曲库；磁盘不足、取消或损坏内容不作为可玩歌曲出现。LazerRave 与 OpenLR2 统一加入同一个 `Shared` 根目录，不要求玩家另外配置路径。

`Shared` 中已安装曲目独立于服务器的 2 小时规则：服务器到期不会删除玩家本地歌曲，支持复用、手动清理和移动至其他正式曲库。未完成暂存采用独立回收策略，避免无限占用本地磁盘；后续实现时须排除用户曲目和暂存文件进入 Git 或编译发行包。

| 限制项 | 初始规划值 |
| --- | --- |
| 压缩包大小 | 128 MiB，与当前小型服务器配置一致 |
| 解压总大小 | 512 MiB |
| 文件数 | 10,000 |
| 临时内容总预算 | 2 GiB，计入全站 8 GiB 内容预算 |
| 未完成上传闲置保留 | 1 小时 |
| 临时曲目保留 | 校验完成后固定 2 小时 |
| 服务端同时校验 | 1 个，其他上传按有界队列等待 |

首期上传会话与临时预算已按上述值实现，临时预算由 `Cloud__MaxTemporaryBytes` 配置。客户端预检默认采用 128/512 MiB 限制，服务端按部署配置执行最终配额。拒绝路径穿越、绝对路径、链接、可执行载荷及 Windows 大小写冲突；设置校验时间、磁盘和并发配额。

临时房间内容不会自动进入公开目录。公开曲目采用独立授权、版本和审核流程。下载授权同时检查成员身份、对象范围和有效期。

## 输入事件回放

新回放记录输入事件，包含文件标识、格式版本、谱面和时间线身份、规则版本、随机种子、游玩修饰、校准参数、事件及结束状态。该格式用于重播和验证，不等同于视频录制或实时观战。

事件时间采用相对游玩时间线的有符号整数微秒，以表示预按键。按下、松开、转盘及同刻事件的顺序须固定。字段宽度、字节序、时间原点和偏移应用位置在 M3 固定，偏移仅应用一次。

旧 `.lr2rep` 通过兼容读取路径保留。缺失元数据明确标记，不补造身份或确定性信息。

| 阶段 | 结果状态 |
| --- | --- |
| 本地记录 | 仅本地、已接收、不完整 |
| M3–M5 结构校验 | 结构有效、结构无效；不代表成绩已重算 |
| M6 规则重算 | 已验证、拒绝、不支持 |

M6 计划通过匹配版本的 OpenLR2 后端重播输入事件、重算统计并比较客户端结果。须先完成无界面重播、随机分支及时间线一致性验证；不支持的引擎版本不能标为已验证。验证失败保留原因，重算任务设置资源上限和超时，并按原生依赖部署独立任务节点。确定性重播不证明输入来自真人。

## 故障与验收场景

协议测试覆盖重复和过期消息、序号异常、错误对局身份、内容或种子不一致、准备后变更、倒计时断线、房主退出、游戏及桌面进程崩溃、服务重启、上传取消、选曲期间换曲、重复上传、授权过期、2 小时固定到期及重启补清理、清理失败与配额回收、磁盘不足、回放截断及事件溢出。内容测试包含异名目录、资源缺失、同歌多难度、已缓存跳过下载、显式下载确认和进度、取消后继续、换曲不自动下载、固定 Shared 安装和暂存排除、下载中到期及已开始演奏不受服务器清理影响。

验证顺序为双真机整局、16 会话与多真机混合测试，再执行 [容量与持续运行测试](../operations/server-capacity.md)。
