# Internet Ranking 与难度表

数据模型参照 [LR2IR 数据集的实体结构](https://github.com/zkldi/lr2ir-dataset/blob/2cabd8972ebe072bcd7c420af1c9b653e8628e08/archive_parser/migrations/0001_schema.sql) 中的用户、谱面、个人最佳和课程关系，并保留本项目的原始成绩与内容身份。数据库迁移版本为 7。未导入 LR2IR 历史数据库，也未将历史玩家自动注册为本站账户。

## 用户身份

`users.id` 为内部 UUID，继续用于会话、曲包、房间和成绩外键。`users.uid` 为对外展示的正整数，不随用户名变化；初始用户按创建时间和 UUID 排序分配。迁移 4 将序列替换为事务计数器，保留既有 UID，并从当前最大 UID 继续取号。注册的 UID 分配、用户插入和登录会话创建在同一事务中完成，失败会回滚计数器；计数器行锁使并发注册串行取号。删除账户不回收编号。

个人资料、管理员用户列表、排名表和桌面联机面板显示 UID。公开资料可通过 `/players/id/{uid}` 页面及 `/api/players/{uid}` 接口访问，原有用户名链接继续有效。本站 UID 与原 LR2IR 的 player_id 属于不同命名空间，不用于证明历史账户归属。

## 成绩与个人最佳

| 数据对象 | 用途 |
| --- | --- |
| `charts` | 原始谱面 SHA-256 身份与用于难度表匹配的 MD5 |
| `ir_boards`、`ir_board_members` | 独立排行榜的元数据、可见性、所有者及私密成员 |
| `scores` | 关联谱面和排行范围的原始演奏记录；可撤销但不删除 |
| `personal_bests` | 按玩家、排行范围、规则、排列、血槽和验证状态生成的最佳记录视图 |
| `courses`、`course_stages`、`course_scores` | 课程、排序谱面及课程成绩的数据库基础；演奏与提交入口尚未接入 |

EX SCORE 由 PGREAT × 2 + GREAT 生成。最高分、最少 BP 和最佳清灯分别聚合，允许来自不同演奏。排行榜同时显示最高分对应的 BP 与历史最少 BP；连击和五类判定来自最高分记录。默认汇总同谱面、同规则下的全部有效排列与血槽，每位玩家显示一条最高分；可按排列、血槽及验证状态缩小范围。同分并列，BP 和 COMBO 不用于破同分；同一玩家同分时选取最早的记录作为明细。

网页提供参与人数、提交次数、通关率及最佳清灯分布，统计与当前筛选一致。每位玩家仅计数一次，EASY 及以上计为通关；同一玩家多次提交不会扩大参与人数。展开成绩详情可查看最高分那次演奏的清灯、普通 SCORE、五类判定和时间；最佳清灯及最低 BP 仍独立展示。谱面标识区展示 MD5 与 SHA-256。曲包取消发布停止下载，不改变 IR 可见性。隐藏排行由独立管理操作完成；迁移前未公开的谱面保留隐藏状态。

`GET /api/rankings/{chart}/summary` 返回筛选后的统计；参数 `arrangement`、`gauge`、`verified` 与排行列表相同。统计查询不修改成绩。普通 SCORE 属于可空字段，旧成绩显示空值，名次始终按 EX SCORE 计算；列表可切换为日期或游玩次数排序。

最大分数尚未提供的旧记录不显示得分率与字母评级，避免从 BAD/POOR 等判定数量推测谱面总音符数。已提供最大分数时按九分制计算 AAA 至 F。客户端提交的最大分数和判定当前仍属于未验证数据，回放重算接入后才能形成可信排名。

## 难度表目录

`difficulty_tables` 保存名称、符号、来源、发布状态和维护者；`difficulty_table_entries` 保存 MD5、等级、标题、作者、来源链接和条目顺序。谱面尚未进入站内曲包目录时也可收录，之后按 MD5 动态匹配公开 IR；存在多个 SHA-256 时选取最早公开的范围作为目录链接，不合并成绩。难度表记录不创建虚假的谱面、资源包或成绩。

网页入口为 `/tables`，按表和等级浏览。已公开登记的谱面提供 Internet Ranking 链接，未入库条目显示其 MD5 与原始来源。登录后显示个人清灯以及每个等级的游玩、通关、HARD+ 和 FC+ 数量；仅统计公开范围，私密与不公开列出成绩均不参与。所有条目分页展示，每页 50 条。

管理员在 Admin 的 Difficulty tables 选项卡填写表名、符号及来源，并上传标准 BMS 难度表 data 文件。文件应为条目数组，至少包含 md5 和 level，可附带 title、artist、url。支持数字或文字等级；同一张表内 MD5 必须唯一。首次保存为草稿，发布后进入公开目录；编辑时完整替换条目列表，保存使用数据库事务，验证失败不会删除现有目录。

| 接口 | 用途 |
| --- | --- |
| `GET /api/tables` | 已发布难度表 |
| `GET /api/tables/{id}` | 表信息与等级列表 |
| `GET /api/tables/{id}/entries` | 按 level 和 page 查询条目 |
| `GET /api/tables/{id}/header.json`、`data.json` | 标准 BMS 难度表头与条目导出 |
| `POST /api/admin/tables`、`PUT /api/admin/tables/{id}` | 创建与完整替换 |
| `PUT /api/admin/tables/{id}/publication` | 发布及取消发布 |

导入文件最多 3 MiB、10,000 条，API 请求上限为 4 MiB。来源链接只接受 HTTP/HTTPS，服务端不主动抓取来源，避免将远程请求与目录导入绑定。所有管理操作记录审计日志。

### 参考范围与现有差距

网页采用 osu! 式的谱面详情、难度切换、玩家资料与成绩详情层级，成绩内容继续使用 LR2 的 EX SCORE、清灯、BP 和判定。保留本站 React、ASP.NET Core 与 PostgreSQL，不整体移植 osu-web，也不改变现有桌面游玩流程。

[osu! 的谱面分类](https://osu.ppy.sh/wiki/en/Beatmap/Category) 区分有排行榜与获得 performance points 的状态；LazerRave 同样将单谱面 IR 与玩家综合能力排名分别设计。本站不直接采用 osu! 的 PP 算法。LR2IR 的谱面、个人最佳、判定、选项与课程字段参考 [归档数据库结构](https://github.com/zkldi/lr2ir-dataset/blob/main/archive_parser/migrations/0001_schema.sql)，不自动导入历史账户或混合历史成绩。

| 范围 | 改造前 | 本轮实现 |
| --- | --- | --- |
| 谱面身份 | SHA-256、MD5 与曲包关联 | 谱面登记独立于 ZIP 发布，精确哈希查询 |
| 客户端查榜 | 标题搜索、分页，再匹配哈希 | 使用精确身份解析，避免标题变化与分页影响 |
| 上传成绩 | 只接受已发布曲包中的谱面 | 允许已登记但没有资源下载的谱面 |
| 网页排行 | 谱面选择侧栏、排行表、筛选及统计 | 独立谱面目录与详情页，排行默认展示 |
| 个人页 | 最近成绩、基础资料 | 个人最佳、清灯记录、历史进步与对手比较 |
| 成绩可信度 | 客户端提交数据、verified 标记 | 明确提交与验证状态，后续接入回放重算 |
| 难度表 | 管理导入、目录、等级与 MD5 匹配 | 无曲包谱面直达 IR，个人清灯覆盖率 |

### 谱面登记与资源分发

IR 以谱面文件内容身份建立，不要求上传 WAV、OGG、BGA 或 ZIP。首次有效提交可登记最小谱面元数据并建立排行榜；后续用户持有相同内容的 BMS 即可进入同一排行榜。首次登记与成绩插入应保持幂等，并处理并发登记。

SHA-256 是本站精确身份，MD5 用于旧 LR2 与难度表查找。MD5 命中但 SHA-256 不同的记录不得直接合并成绩，应进入别名确认或版本处理。同名、同目录名或相同音频不能证明谱面相同；修改 BMS 内容后形成独立版本，旧成绩保留在旧身份下。不同资源目录不影响相同 BMS 的匹配。

初期可仅接收客户端提供的哈希与受限元数据，该方式不能证明客户端确实持有相应文件，也不能证明音符数正确；记录保持 Submitted。后续可支持独立的 BMS 文件或结构清单校验，不要求连带上传音频和视频。已登记谱面的权威元数据不得由普通后续提交覆盖；冲突需要管理审核。

下载与 IR 使用独立状态：取消曲包发布只停止该曲包下载，不自动删除已有 IR；禁用排行或隐藏谱面由独立管理操作完成。已有取消发布内容仍保持其当前可见性，迁移不能自动重新公开。房间临时 ZIP 到期删除后，按允许的可见性保留谱面身份与成绩，不保留临时下载链接。

客户端仅在玩家提交成绩或明确启用自动提交后登记相关谱面，不上传完整本地曲库清单、绝对路径或私有目录结构。

### 本地曲目与私密排行榜

没有站内 ZIP 的本地曲目可以有 IR。“未提供下载”和“私密”分别处理。

| 排行可见性 | 访问规则 | 公开目录与综合统计 | 资源下载 |
| --- | --- | --- | --- |
| Public | 所有人可查看、搜索 | 可进入公开目录；综合统计另受审核状态约束 | 可有或没有 ZIP |
| Unlisted | 可通过链接或精确身份直达，不提供搜索列表 | 不进入公开推荐及综合榜；公开个人页不自动列出 | 可有或没有 ZIP |
| Restricted | 仅所有者和明确授权成员可访问 | 不进入公开目录、个人记录与公共统计 | 由独立资源权限决定 |

普通本地曲目默认自动提交至 Public 社区范围，登记后直接进入公开目录，无需管理员先批准。玩家可选择自动提交至 Restricted 私人范围，或关闭自动上传。管理员保留隐藏谱面及撤下成绩的渠道；隐藏不会被重复登记解除。Unlisted 用于显式创建的链接访问范围。

内部谱面身份可以去重，公开元数据与排行权限应绑定具体排行榜或发布记录。相同哈希可对应独立的私密范围和公开范围，首位登记者不能独占全站该哈希。私密成绩不会因其他人公开相同谱面而自动进入公开榜，也不会随房间关闭自动公开。

鉴权覆盖谱面详情、排行与统计、难度表匹配、玩家最近成绩、个人最佳、成绩详情、回放及分享入口。未授权查询不泄露私密谱面的标题、参与人数或存在性；私密范围变化不得复用公开缓存。公开转换需要明确确认并保留审计记录。管理隐藏保留成绩与原因，不将隐藏等同于删除。

### 成绩规则与展示

1. 默认按 EX SCORE 降序，每位玩家展示一条个人最佳；同分并列，BP、COMBO、提交时间不破同分。
2. 最高 EX SCORE、最低 BP 和最佳清灯独立聚合，不拼接成一次虚构演奏。判定与本次清灯来自最高分记录。
3. 展示 PGREAT、GREAT、GOOD、BAD、POOR、普通 SCORE、最大 COMBO、得分率及 AAA 至 F。普通 SCORE 保留为详情，不代替 EX SCORE 排序。
4. 榜单身份包括谱面、规则版本、键型和访问范围。单谱面默认合并既有合规排列与血槽，可按这些选项筛选；改变判定或计分规则的扩展需要独立规则或练习记录。
5. 自动演奏、辅助、MANIAC、不完整演奏继续不进入正常 IR。失败但完整结束的正常演奏可以保留 FAILED 成绩。
6. Submitted 表示客户端提交；Verified 只能用于实际通过对应版本验证的成绩。格式校验、身份摘要或客户端完整性检查不等同于回放重算。
7. 已审核谱面也不代表其全部成绩可信。谱面审核、排行可见性、成绩验证是三个独立状态。

首期不以全库 EX SCORE 求和生成综合实力榜，避免长曲、密集谱面和重复版本带来不合理优势。优先提供难度表内的清灯分布、覆盖率及单谱面排名；课程认证与综合能力指标在明确曲目范围和算法后接入。无审核谱面可以保留单谱面 IR，但不自动贡献综合能力排名。

| 页面 | 内容与交互 |
| --- | --- |
| IR 首页与谱面目录 | 标题、作者、键型、等级、难度表、排行状态筛选；默认 7Key；查询状态写入 URL，分页可返回 |
| 谱面详情 | 标题、作者、键型、等级、BPM、时长、身份与来源；有可靠同曲关系时显示难度页签；默认展示排行榜 |

| 成绩详情 | 完整判定、普通 SCORE、COMBO、当次清灯、演奏选项、日期、客户端与规则版本、验证状态；独立地址可分享，回放入口按实际可用状态显示 |
| 玩家页 | 资料、最近公开成绩、个人最佳、清灯统计和历史进步；所有者在登录后另看非公开记录 |
| 难度表 | 等级分组、谱面 IR、玩家清灯及覆盖率；未匹配条目保留来源，不伪造成绩或谱面身份 |
| 管理后台 | 谱面元数据冲突、公开收录、隐藏及恢复、成绩撤销、异常记录与审计；不依赖曲包发布来管理 IR |

谱面详情以排行为主体，不保留常驻左侧谱面选择列表。主表减少列宽负担，PG/GR/GD/BD/PR 和完整选项放入成绩详情，窄屏保留玩家、EX SCORE、评级和清灯。中英文本、日期、数字及筛选状态沿用现有持久化语言系统。

同曲难度关系应来自可信的曲目分组或管理确认，不能仅按标题自动合并。缺少封面或站内资源时使用现有品牌占位，不能自动读取玩家本地素材上传到公开网站。网站继续不恢复多人大厅入口。

### 登记与网页入口

设置的 Internet Ranking 中提供“自动上传”“自动上传（私有）”“不上传”，持久化字段为 `ir_upload`，取值分别为 `public`、`private`、`off`，默认 `public`。仅已登录且符合排名条件的真实演奏自动提交，回放、自动演奏和不合格成绩不提交。成绩先保存至本地，再后台上传，上传不阻塞退出游戏；失败后可从成绩右键菜单重新提交。菜单提供“提交至公开 IR”和“提交至私密排行榜”。普通提交首次建立 Public 社区范围；私密提交首次建立玩家自己的 Restricted 范围。相同演奏可以明确分别提交两个范围，重试按用户、范围和演奏 ID 去重；私密记录不会自动复制到社区榜。登记前重新计算当前 BMS 哈希，谱面内容已改变时拒绝提交原成绩。

网页 `/rankings/mine` 展示本人建立、获邀或已提交的可访问范围，并提供仅元数据的登记表单。所有者可邀请或移除 UID 成员；Unlisted 所有者确认后可公开社区范围。Restricted 不允许直接公开，必须另建社区范围并明确提交。管理员在 Charts 选项卡管理社区范围的公开、隐藏和恢复，不列出私密范围。

| 接口 | 范围 |
| --- | --- |
| `POST /api/charts/register` | 已登录用户登记 Public、Unlisted 或 Restricted；不接收曲包和本地路径 |
| `GET /api/charts/resolve?sha256=…` | 精确解析可访问的社区范围；不解析他人的私密范围 |
| `GET /api/charts?mine=true` | 本人建立、获邀或提交过的可访问范围 |
| `PUT /api/charts/{id}/visibility` | 确认公开及管理隐藏/恢复；Restricted 禁止公开转换 |
| `GET/POST /api/charts/{id}/members`、`DELETE /api/charts/{id}/members/{uid}` | 所有者管理私密成员 |
| `GET /api/rankings/{id}/me`、`history` | 筛选后的个人排名与本人最近演奏 |
| `GET /api/scores/{id}` | 遵循范围权限的独立成绩详情；不公开管理审核备注 |
| `GET /api/players/{uid}/records`、`compare?against=…` | 个人最佳/最近成绩、两位玩家的公开共同谱面比较 |
| `GET /api/admin/charts` | 社区范围管理目录，含隐藏内容，不包含私密范围 |
| `PUT /api/admin/scores/{id}/review` | 带审核原因撤销或恢复成绩，所有聚合排除撤销记录 |

谱面、排行、个人成绩、比较和难度表按每页 50 条分页，个人历史最多返回 100 条。登记限制为每用户每分钟 60 次，并继续受全局请求限制。API 响应不允许浏览器缓存，登录身份变化时清除网页已有查询，防止退出后继续展示私密数据。管理员权限不自动授予私密谱面或成绩的读取权限。

### 当前服务器约束

首期继续使用现有 1 vCPU、1 GiB、32 GB 主机的 React 静态资源、ASP.NET Core 与 PostgreSQL，不增加 Redis、搜索集群或独立微服务。精确哈希查找使用索引；谱面与排行分页有界，榜单、统计和个人名次共享相同筛选与权限。数据增加后维护个人最佳快照并对常用公开查询使用短时缓存，避免每次网页刷新重算完整成绩历史。

排名缓存以谱面、范围、规则、筛选和更新版本区分；私密请求先鉴权再访问缓存。排名查询与聚合需要实际测量查询计划、内存和响应时间后调整，不能仅依据现有规格承诺容量。回放重算不在当前 API 主机上同步执行，后续使用独立任务节点并限制队列与存储配额。

### 演奏时间与浏览排序

`scores.played_at` 保存客户端记录的真实演奏开始时间（UTC），`created_at` 保留服务器接收时间。上传旧本地成绩时使用其已有 `PlayedAt`，不使用当前上传时间。演奏开始时间以引擎首个有效成绩快照为准；该时间仍属于客户端报告数据，不代表回放验证。日期不得早于 2000 年或超出服务器当前时间十分钟。迁移前未提交真实时间的记录保持空值，网页显示破折号，可通过重复提交相同本地记录补充时间；不得推算或伪造旧演奏日期。重复请求按微秒统一时间精度并保持幂等。

谱面目录支持标题与作者搜索、键型、难度类型、等级区间以及最新谱面、最新游玩、游玩次数、等级升降序和标题排序。游玩次数统计有效且未撤下的已提交记录，参与人数按玩家去重；不包含未上传的本地演奏。单谱面排行榜支持 EX SCORE、日期和游玩次数排序；每位玩家仍展示最高分明细，EX SCORE 同分仍并列。过滤条件和排序保存在网页 URL，切换条件后返回第一页。

迁移 7 将既有未被审核隐藏的 Unlisted 社区范围调整为 Public，Restricted 和 Hidden 保持原状态。新增真实时间字段不修改既有成绩 ID、分数或上传日期。
